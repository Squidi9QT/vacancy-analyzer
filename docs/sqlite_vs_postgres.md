# PostgreSQL против SQLite: что пришлось бы менять

Docker на машине разработки не было, но был установлен PostgreSQL 16, поэтому SQLite-fallback не понадобился. Ниже — что изменилось бы, если бы пришлось перейти на SQLite. Это частый вопрос на собеседовании: «почему не SQLite?»

**SQLite** — база данных в одном файле, без сервера. Встроена в Python (`import sqlite3`).

| Тема | PostgreSQL 16 | SQLite 3.45+ | Что меняем |
|------|---------------|--------------|------------|
| Автоинкремент | `BIGINT GENERATED ALWAYS AS IDENTITY` | `INTEGER PRIMARY KEY` (ROWID) | Синтаксис первичных ключей |
| Время | `TIMESTAMPTZ` — настоящий тип с поясом | Нет типа дат: хранится строка ISO-8601 или число | Сравнения дат работают как сравнения строк — нужен единый формат и пояс |
| Строгость типов | Строгая: в `INTEGER` строку не записать | «Type affinity»: в `INTEGER` можно записать `'abc'` | Без `STRICT`-таблиц мусор пролезет; проверки переносим в Python |
| `JSONB` | Бинарный JSON с индексами | `JSON` хранится как текст, функции `json_extract` | `load_run.params` → `TEXT` |
| `ON CONFLICT ... DO UPDATE` | Есть | Есть с 3.24 (2018) | Работает почти так же; `EXCLUDED` поддерживается |
| `RETURNING` | Есть | Есть с 3.35 | — |
| `xmax = 0` (понять, вставка или обновление) | Есть (системная колонка) | Нет | Сравнивать счётчики `changes()` или делать SELECT |
| Оконные функции | Полностью | Есть с 3.25 (ROW_NUMBER, LAG, рамки) | — |
| `percentile_cont` (медиана) | Есть | **Нет** | Считать медиану в pandas или через `ROW_NUMBER` + `COUNT` |
| `FILTER (WHERE ...)` в агрегатах | Есть | Есть с 3.30 | — |
| `GROUPING SETS` | Есть | **Нет** | `UNION ALL` двух группировок |
| `date_trunc`, `make_interval` | Есть | Нет | `strftime('%Y-%m', ...)` |
| Частичный уникальный индекс | Есть | Есть (`CREATE UNIQUE INDEX ... WHERE`) | — |
| `CHECK` с регулярными выражениями (`~`) | Есть | Нет оператора `~` | Убрать или проверять в Python |
| `EXPLAIN ANALYZE` | Реальное время и строки по каждому узлу | Только `EXPLAIN QUERY PLAN` — план без времени | Замеры скорости — в Python (`time.perf_counter`) |
| Параллельная запись | Много писателей одновременно | Один писатель на файл | Для одного студента не проблема |
| Плейсхолдер параметров | `%s` (psycopg) | `?` (sqlite3) | Все запросы в коде |

**Вывод.** SQLite подходит для прототипа и тестов. Для этого проекта PostgreSQL лучше: медиана, `GROUPING SETS`, строгие типы дат и честный `EXPLAIN ANALYZE` — ровно то, что мы изучаем.
