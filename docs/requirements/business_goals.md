# Бизнес-цели проекта «Анализатор вакансий»

## Зачем проект существует

Студент готовится к работе системного аналитика. Ему нужно понимать рынок: какие навыки просят, сколько платят, кто нанимает. Читать сотни вакансий руками долго, и выводы получаются субъективными. Сервис собирает вакансии автоматически и отвечает на вопросы цифрами.

Вторая цель — учебная. Проект проходит весь путь системного аналитика: требования → модель данных → загрузка → SQL → отчёт. Каждое решение можно защитить на собеседовании.

## Цели

| # | Цель | Как поймём, что достигнута (метрика) |
|---|------|--------------------------------------|
| G1 | Знать, какие навыки учить первыми | Есть рейтинг топ-20 навыков для аналитиков с долей вакансий, где навык упомянут |
| G2 | Понимать уровень зарплат и его динамику | Медиана зарплаты по месяцам, ролям и городам; видно, на скольких вакансиях она посчитана |
| G3 | Знать активных работодателей | Топ работодателей по числу вакансий и частоте обновлений; список компаний, нанимающих 3+ месяца подряд |
| G4 | Оценить прозрачность рынка | Доля вакансий без зарплаты по городам |
| G5 | Не пропускать новые вакансии | Список вакансий, впервые появившихся за 7 дней, без дублей |
| G6 | Данным можно доверять | Повторная загрузка не создаёт дублей (проверяется тестом); каждый запуск записан в журнал `load_run` |

## Метрики качества самой системы

- **Идемпотентность:** два запуска подряд за тот же период дают одинаковое число строк во всех таблицах.
- **Полнота загрузки:** число загруженных вакансий = `found` из ответа API (с учётом лимита 2000 на поиск).
- **Время загрузки 7 дней:** до 5 минут при паузе 0,5 с между запросами.
- **Воспроизводимость:** на фикстурах любой человек получает те же цифры, что в отчёте.

## Что не входит в проект (границы)

- Не рекомендуем вакансии и не откликаемся на них.
- Не парсим HTML-страницы сайта — только официальный API.
- Не храним персональные данные (контакты рекрутеров не загружаем).
- Не прогнозируем зарплаты — только описываем то, что было.
