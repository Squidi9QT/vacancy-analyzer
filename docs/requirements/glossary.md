# Глоссарий

Полная версия с поиском — в разделе «Глоссарий» сайта `explainer/index.html`. Здесь — основные термины.

| Термин | Простыми словами | Пример из проекта |
|--------|------------------|-------------------|
| **Вакансия** | Объявление работодателя о поиске сотрудника. Для нас вакансия — это запись с уникальным id на hh.ru. | `hh_id = 104857600`, «Системный аналитик», Томск |
| **Внешний id (hh_id)** | Идентификатор, который присвоил источник данных, а не наша база. | Колонка `vacancy.hh_id`, по ней работает `ON CONFLICT` |
| **Суррогатный ключ** | Искусственный номер строки, который создаёт наша база. Ничего не значит в реальном мире. | `vacancy.id BIGINT GENERATED ALWAYS AS IDENTITY` |
| **Дедупликация** | Удаление повторов: одна сущность должна храниться один раз. | Две загрузки одной вакансии дают одну строку благодаря `UNIQUE(hh_id)` |
| **Медиана** | Значение «посередине»: половина зарплат ниже, половина выше. В отличие от среднего, не ломается от одной огромной зарплаты. | `percentile_cont(0.5)` в q2 |
| **SCD (slowly changing dimension)** | Способ хранить историю медленно меняющихся данных. Тип 1 — перезаписываем, тип 2 — храним все версии с периодом действия. | `vacancy` — тип 1, `vacancy_snapshot` — тип 2 (`valid_from`, `valid_to`) |
| **ETL** | Extract — Transform — Load: достать данные, привести к нужному виду, загрузить. | `src/extract`, `src/transform`, `src/load` |
| **Идемпотентность** | Свойство операции: повторный запуск даёт тот же результат, что и первый. | `load --days 7` дважды → одинаковое число строк |
| **Нормализация** | Раскладка данных по таблицам так, чтобы каждый факт хранился в одном месте. | Навыки в `skill` + `vacancy_skill`, а не строкой через запятую |
| **Upsert** | «Вставь, а если такая запись уже есть — обнови». | `INSERT ... ON CONFLICT (hh_id) DO UPDATE` |
| **Retry / backoff** | Повтор запроса после ошибки с растущей паузой. | 1 → 2 → 4 → 8 с при ответе 429 |
| **Rate limit** | Ограничение API на число запросов в единицу времени. | Ответ 429 Too Many Requests |
| **CTE** | Именованный подзапрос в `WITH`, делает SQL читаемым по шагам. | `WITH first_salary AS (...)` в q2 |
| **Оконная функция** | Считает значение по группе строк, но не схлопывает их. | `ROW_NUMBER() OVER (PARTITION BY ...)` |
| **Gaps and islands** | Приём поиска непрерывных серий («островов») в последовательности с пропусками. | Компании, нанимающие 3+ месяца подряд (q6) |
| **ADR** | Architecture Decision Record — короткая запись: контекст, варианты, решение, последствия. | `docs/decisions/` |
| **Индекс** | Отдельная структура, по которой база быстро находит строки, как оглавление в книге. | `idx_vacancy_published_at` |
| **EXPLAIN ANALYZE** | Команда, которая выполняет запрос и показывает, как именно база его выполняла и сколько времени ушло. | `docs/query_plans/` |
| **Параметризованный запрос** | Запрос, где значения передаются отдельно от текста SQL. Защищает от SQL-инъекций. | `cur.execute("... WHERE hh_id = %s", (hh_id,))` |
| **ORM** | Библиотека, которая превращает таблицы в классы и пишет SQL за вас. | В проекте не используется, см. ADR-006 |
| **Фикстура** | Заранее сохранённые тестовые данные. | `tests/fixtures/` — ответы API в формате JSON |
| **Gross / net** | Зарплата до вычета налога (gross) и «на руки» (net). | Поле `salary.gross` в API hh.ru |
