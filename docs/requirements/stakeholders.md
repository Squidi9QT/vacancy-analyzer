# Заинтересованные лица и акторы

**Стейкхолдер** — тот, на кого влияет система или кто влияет на неё. **Актор** — тот, кто напрямую взаимодействует с системой (человек или другая система).

| Актор | Кто это | Чего хочет | Как взаимодействует | Что для него важно |
|-------|---------|------------|---------------------|--------------------|
| Студент-аналитик | Основной пользователь, он же заказчик | Понять рынок и подготовиться к собеседованию | Запускает загрузку, пишет SQL, смотрит графики и сайт-объяснение | Правдивые цифры, понятные объяснения |
| Рекрутер-наблюдатель (условный) | Человек, которому студент показывает проект | Оценить, умеет ли студент думать как аналитик | Читает README, отчёт, задаёт вопросы | Обоснованность решений, аккуратность |
| Система (планировщик / cron) | Автоматический запуск раз в сутки | Выполнить ежедневное обновление | Вызывает `python -m src.main load --days 1` | Код возврата, журнал `load_run` |
| API hh.ru | Внешняя система — источник данных | Чтобы клиенты соблюдали правила | Отдаёт JSON, может ответить 429/403/5xx | User-Agent с контактом, паузы между запросами |

## Почему рекрутер «условный»

Реального рекрутера в проекте нет. Мы добавляем его, чтобы помнить: результат будут читать другие люди. Это меняет требования: нужен README, нужны объяснения, нужны воспроизводимые данные.

## Конфликты интересов

- **Студент хочет больше данных, API hh.ru — меньше нагрузки.** Решение: качаем только нужные роли и период, ставим паузу между запросами, детали вакансии запрашиваем один раз (дальше — только если вакансия изменилась).
- **Рекрутер хочет понять быстро, студент хочет показать всё.** Решение: README с запуском за 5 минут и `docs/summary.md` на одну страницу; детали — в сайте-объяснении.
